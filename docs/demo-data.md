# Real places, sample flights

Run `node scripts/seed-demo-catalog.js` from the repository root after auth and the flight service are running. First run `node scripts/create-local-admin.js` once; the seed signs in using the ignored local admin credentials. The script uses the local flight-service API and adds six cities, six airports, one demo aircraft, and **100 sample flights across all 30 directed routes** between those six airports. The [complete schedule CSV](demo-flight-schedule.csv) lists each flight number, airline, origin/destination cities and airports, India-time departure/arrival, fare, and available seats. It checks names and flight numbers before creating records, so a second run skips what is already present. It never deletes or rewrites existing bookings or test fixtures. Set `FLIGHT_API_URL` to use a different local flight-service address.

The city, airport and airline **names and codes are real**. These airport names and codes are supported by Air India's airport guides: [Delhi (DEL)](https://www.airindia.com/jp/en/travel-information/airport-information/delhi.html), [Mumbai (BOM)](https://www.airindia.com/en-us/book-flights/flights-to-mumbai), [Bengaluru (BLR)](https://www.airindia.com/content/air-india/in/en/travel-information/airport-information/bengaluru.html), [Hyderabad (HYD)](https://www.airindia.com/en/book-flights/flights-from-hyderabad), and [Chennai (MAA)](https://www.airindia.com/in/en/travel-information/airport-information/chennai.html). The Kolkata name uses [AAI's spelling](https://www.aai.aero/sites/default/files/NM_CCU_Jun24_RevC_Final_Submission%20signed.pdf), and its CCU code is shown in [Air India's Kolkata guide](https://www.airindia.com/in/en/travel-information/airport-information/kolkata.html). The airline prefixes follow [Air India's AI code](https://www.airindia.com/in/en/vistara-air-india-merger-faqs.html), [IndiGo's 6E code](https://www.goindigo.in/domestic-flights.html), and [Akasa Air's QP code](https://www.akasaair.com/flight-status).

The seeded **flight numbers, routes, departure times, aircraft assignment and fares are fictional examples**. They are not imported from airline schedules or connected to airline inventory. New flights span four days beginning seven days after seeding, using the India calendar date. The original eight demo flights retain their existing dates and inventory. Repeated runs leave all existing flights intact even after their departure dates. The CSV is refreshed from the stored records each time the script runs. This project processes local demo reservations only and does not buy tickets from those airlines.

The customer search prioritizes airports with a three-letter code in their name, so old load-test fixtures no longer crowd its dropdown. The admin catalog still lists all records. Popular-route buttons fill the search form; press **Search flights** to see the sample flights.

The 2026-10-06 expansion created 92 flights and retained the existing eight. A repeat created zero flights and skipped all 100. The exported schedule contains 100 unique flight numbers, covers 30 directed routes, and has arrival after departure for every flight.
